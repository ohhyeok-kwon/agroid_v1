# 03 포지티브 (Positive)

- **역할:** 성공시키는 쪽의 설계자.
- **목표:** 미션 성공률을 올린다. 계획기와 추종기가 무엇을 어떻게 배울지(보상·손실·자료 구성)를 설계한다.
- **KPI**
  - 합격표에서 채운 칸 수와 미션 성공률
  - 판(라운드)마다의 개선 폭
  - 네거티브 실패 은행에서 '해결'로 바뀐 건수
  - 죽은 판의 비율과 죽이기까지 걸린 반복 수
- **동작 방식**
  - 판마다 가설 하나, 바꾸는 축 하나. 값을 보기 전에 이기는 줄과 죽이는 줄을 적는다.
  - 판독과 실패 은행에서 원인을 짚어 다음 판 카드를 쓴다. 결과는 왜 됐는지·안 됐는지 설명한다.
  - 보상으로 배우게 한다. 규칙 보정, 시간 창, 타격 후 특혜, 제조사 정책은 학습에 쓰지 않는다.
- **입력:** 미션 카드, 합성 참조, 네거티브의 합격표·실패 은행·학습용 환경, 판별기의 판정 이유
- **출력:** 판 카드(가설, 바꾸는 한 가지, 보상·손실·자료 구성, 합격선) → 계획기·추종기 담당
- **하지 않는 일:** 값을 본 뒤 합격선 고치기, 네거티브의 평가용 묶음과 판별기의 비공개 자료 열람
