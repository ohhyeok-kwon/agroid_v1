# 학습 구조

로봇에 실리는 모델은 둘이고, 아홉 역할의 에이전트가 동작을 한 칸씩 늘려 가며 그 둘을 만든다.
역할별 목표·KPI·입출력은 [roles/](roles/) 문서를, 학습 원칙은 [12_train.md](12_train.md)를 따른다.

## 모델

| 모델 | 하는 일 | 주기 |
|---|---|---|
| 계획기 | 명령(속도·방향·높이)을 받아 앞으로의 전신 참조 동작을 낸다 | 10 Hz |
| 추종기 | 참조를 균형 잡으며 관절 목표로 따라간다 | 50 Hz |

## 한 칸(동작 하나)의 흐름

1. 코디네이터(조율자)가 다음 칸의 최종 목표 표와 담당별 목표 지점을 정한다([motions/](motions/)).
2. 서플라이어(공급기 담당)가 그 동작의 원본을 모아 동작 카드로 낸다.
3. 신시사이저(합성기 담당)가 로봇 기준의 합성 참조를 설계해 학습 자료로 만든다.
4. 포지티브가 보상·손실·자료 구성을 판 카드로 정한다.
5. 플래너(계획기 담당)와 트래커(추종기 담당)가 판 카드대로 학습하고 판독한다.
6. 네거티브가 어려운 환경과 미션에서 시험하고 실패를 쌓는다.
7. 디스크리미네이터(판별기 담당)가 품질을 판정한다.
8. 통과하면 인티그레이터(연동 담당)가 Operation Center 에 올리고, 다음 칸으로 간다. 시한이나 방법이 다하면 현역을 두고 미달 행을 같은 선으로 다음 칸의 표에 이월한다.

## 공통 규칙

- 사람 동작과 로봇 동작은 지향점이 다르다. 계획기는 손으로 설계한 합성 참조만 배운다.
- 사람·큰 모델의 원본은 설계의 참고와 추종기의 동작 폭 유지에만 쓴다.
- 칸의 순서는 평지 걷기 → 험지 걷기(계단·문턱·자갈밭·경사로) → 머리 스테레오 카메라 장애물 감지·충돌 회피 → 웅크리기 → 균형잡기 → 집기·옮기기·놓기다(앞의 셋은 사용자 11-22). 모델은 계획기 하나, 추종기 하나다.
- 두 관문은 침착함과 바른자세다. 합격선은 값을 보기 전에 정하고, 한 판은 가설 하나·축 하나다.
- 포지티브와 네거티브는 적대 관계다. 평가용 묶음과 판별기 자료는 포지티브에게 주지 않는다.
- 제조사 정책·모델은 평가에만 쓴다. 실행 중 규칙 보정·시간 창·대칭화는 쓰지 않는다.
- GPU 4 장은 모델 하나에 쓰고 판은 차례로 돈다. PC 에서는 계산하지 않는다.
- 사용자에게 평가·결정을 시키지 않는다. 작업 기록은 `.agent/adversarial/rounds/<판>/` 에 둔다.
- 현재(11-21 19:58 확인): 실행(Operation Center·공식 합격표)의 참조는 신시사이저의 실시간 생성기가 낸다. 학습된 계획기는 합성기가 굳은 뒤 옮겨 배운다.
- 현재: Operation Center 에서는 추종기 추론이 노트북에서 돈다(판정은 지연 15 ms 칸). R1 에는 11-22 에 추종기 R14@100 과 구운 참조 묶음을 설치했다(로봇 보드에서 추론 · 11-22 사용자가 실기 보행 확인). 평지 걷기 칸은 11-22 08:22 에 '조기 종료'로 닫았고(미달 8 행은 같은 선으로 이월), 험지 걷기 칸은 11-22 19:36 사용자 지시로 1차를 마무리했다(채택 판 없음 · 2차는 사용자 지시 뒤). 모션별 설계는 [motions/](motions/)에 있다. 웅크리기 칸은 높이 범위만 재고 멈췄다.
