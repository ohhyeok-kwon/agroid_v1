# DTC

**200 정상 · 201 경고 · 202 fault(오류).** `/humanoid_status`는 아래 순서의 8개 코드를 1Hz로 발행한다.
미점검은 202, 경고는 다음 부팅 단계 진행, 오류는 해당 단계를 재점검한다. 완료 후에도 계속 감시한다.

| 매니저 | 201 경고 | 202 fault |
|---|---|---|
| cpu_manager | 사용률 ≥90%·비교 샘플 없음·유효하지 않은 측정 구간 | CPU 통계 읽기·해석 실패 |
| temp_manager | 최고 온도 ≥90℃ | 온도 센서 없음·읽기·해석 실패 |
| memory_manager | `(전체−가용)/전체` ≥95% | 메모리 통계 오류 |
| disk_manager | `/` 가용 공간 <20% | 읽기 전용·파일시스템 통계 오류 |
| network_manager | lo 외 UP+RUNNING IPv4 없음 | 인터페이스 조회 실패 |
| battery_manager | controller의 201 전달 | 202·미수신·3초 초과·형식 오류 |
| humanoid_controller | `/motor_status`의 201(초기화 등) | 202·미수신·3초 이상 중단·형식 오류 |
| remote_controller | 연결 상태의 201 | 미연결·202·미수신·3초 이상 중단·형식 오류 |

BMS는 잔량 **5% 미만**, USB 미연결·송수신 실패·부분 송신, 미수신·3초 초과, CRC·조각·SOC/SOH 오류가 202다.
정확히 5%는 정상, BMS 자체 201 조건은 없다. 정상 데이터가 남아 있어도 오류를 숨기지 않는다. [BMS](06_bms.md).
모터는 USB·MCU 미수신/3초 초과, 26개 중 누락, 헤더·ID·CRC·모터 fault·통신 timeout·초기화 실패가 202다.
설정 불일치·E2 echo·F1 응답 오류·초기화 후 15초 피드백 미확보도 202다. warning_code·초기화·영점 미검증은 201이다.
머리 응답 100ms 미수신·250ms 동일, FOC 미진입·범위 초과·역방향·정렬/탐색/해제 실패도 202다. [초기화](07_mcu.md).
200은 모터 26개·초기화·머리 기준점·구동 해제 통과다. 실패 시 mode 0 해제·모션 차단, 자동 재탐색은 없다.
빈 슬롯은 고장으로 단정하지 않으며 미구성 주소는 판정에서 제외하고 원본을 보존한다.
리모컨 패킷 나이 <250ms는 200, 250~749ms는 201, ≥750ms·미수신은 202다. 201/202는 미연결로 처리한다.
MCU CRC·RF 체크섬·순서·시각 오류는 해당 입력만 버리고 오류 수를 기록한다. 시간 판정은 단조 시계다.
TF는 USB 단절·3초 초과·유효 관절 0개면 중단하고, 그 외에는 유효 관절만 보낸다. 앱은 빠진 관절의 마지막 값을 유지한다.

현재 모든 안전 레이어와 warning/fault 스위치는 OFF다. 아래는 [설정](../src/safty_manager/config/default.yaml)에 보존한 활성화 시 기준이다.

| 안전 모듈 | 201 경고 | 202 fault |
|---|---|---|
| command_format | 없음 | CRC·모델·숫자·게인 형식 오류, 미구성 슬롯 명령 |
| joint_range | 관절 한계까지 여유 <0.10rad | 제조사 범위에서 0.00175rad 넘게 이탈·유효하지 않은 위치 |
| sudden_motion | 한 번에 >0.05rad 또는 목표-측정 >0.10rad | 한 번에 >0.10rad 또는 목표-측정 >0.25rad |
| speed | 목표 속도·목표 변화율·실측 속도 >0.2rad/s | 같은 값 >0.5rad/s 또는 유효하지 않은 속도 |
| boot_status | 201 또는 토픽 >2초 | 202·형식 오류·미수신 또는 >3초 |
| feedback | 관절 피드백 >250ms | 미수신 또는 >500ms |

범위·급변은 목표와 실측을 검사한다. 위치 목표가 없는 zero/damping의 q는 목표 검사에서 제외한다.
boot_status·feedback은 시작 후 10초 유예한다. 목표 변화율은 최소 20ms 구간으로 계산한다.
각 모듈 `enable`, `warning.enable`, `fault.enable`로 구분 설정한다. command_format은 fault 전용이다.
201은 경고만 표시한다. 202는 위험 명령을 막고 state_manager에 locked standing을 요청한다.
기립은 최신 완전한 측정에서 최대 0.1rad/s로 시작하며, 기립 명령도 안전 검사를 통과해야 한다.
통신·센서 fault 중에는 해당 기립 목표와 명시적 damping만 허용한다. 기립 생성·전달은 실제 자세 유지 확인과 다르다.
fault가 사라지고 교정 명령을 전달한 뒤 1초가 지나면 해제한다. 보행 자동 재개는 없다. 설정 변경은 재시작 시 적용한다.
L2+B 감쇠는 우선한다. 기존 보행 과기울기·계산 실패·380ms 명령 중단의 감쇠도 유지한다.
controller의 패킷 검증·USB 초기화는 별도다. 전원·모터·USB 장애 또는 균형 상실 시 기립을 보장하지 않는다.
