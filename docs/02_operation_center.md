# Operation Center

```bash
./scripts/01_operation_center.sh                        # 데스크톱
./scripts/01_operation_center.sh --headless --port 8797 # 브라우저
./scripts/01_operation_center.sh --build-only           # 빌드만
```

- PC의 Node.js·npm이 필요하고, 데스크톱은 Rust·WebKitGTK 4.1 개발 환경도 필요하다.
- 메뉴 아이콘은 `scripts/01_operation_center.sh`를 도메인 `0`으로 실행한다.
- 로봇 패키지의 PC 빌드·R1 배포는 [03_deploy.sh](01_initial_setup.md)로 수행한다.
- ROS가 없어도 3D 모델과 Simulation 화면은 실행된다. Simulation에는 `.agent/trainer/.venv`와 EGL 렌더링 환경이 필요하다.
- ROS 기본 경로는 `/opt/ros/jazzy/setup.bash`이며 `AGROID_ROS_SETUP`으로 지정한다.
- 빌드·캐시는 `.agent/operation_center/`, PC ROS 결과는 `.agent/ros2/`에 둔다.
- ‘관절 위치’를 켜면 관절·골반 IMU·좌우 카메라 위치가 함께 표시된다.
- 좌표가 없는 메인보드 IMU는 위치 미확인으로 안내한다. [센서](11_sensors.md).
- 3D 화면은 R1 모델을 표시한다. 드래그 회전·휠 확대·우클릭 이동을 지원한다.
- 시작 창·카메라 값은 `app/operation_center/startup.json`, 모델 출처는 `assets/robot/source.json`에 둔다.
- 자세는 로컬 ROS의 `/tf`·`/tf_static`으로 수신한다. `/tf` 메시지 1개를 한 측정으로 보고 받은 관절을 갱신한다.
- R1이 뺀 관절은 마지막 각도를 유지하고 각도 칸 `—`, 상태 문구에 미수신 관절을 표시한다.
- 3D 모델은 TF의 관절 이동·회전을 직접 적용한다. 숫자 각도도 같은 TF에서 계산한다.
- 기준 좌표계는 `pelvis_link`다. 전신 위치·기울기와 IMU는 미측정이며 자세 각도 칸은 `—`로 표시한다.
- R1·PC 시스템 시각을 맞춰야 한다. 3초 이상 지난 TF는 사용하지 않고 수신 중단 시 마지막 자세를 표시한다.
- 같은 시각·1초 미만 역행 TF는 건너뛰고, 1초 이상 역행은 R1 시계 조정으로 보고 계속 표시한다.
- 실제 R1 발행 목록은 [토픽](08_topic.md)을 기준으로 한다.

## Simulation(임시)
- `http://127.0.0.1:8797/#simulation`에서 Walking으로 시작한다. 로봇 기준 W/S 전진·후진, A/D 좌측·우측 이동이다.
- 휠 클릭 드래그는 자유 시점만 바꾼다. 우클릭 드래그는 시점과 Walking·Careful Walk·사람 모션 교사·통합 정책·DynamicMode의 보행 방향을 함께 바꿔 화면 앞쪽으로 걷게 한다. 휠 스크롤은 확대·축소다.
- 화면은 MuJoCo가 렌더링한 960×600 MJPEG(목표 60fps), 물리 1kHz, 보행 정책 50Hz다. 데스크톱 WebKitGTK 2.52는 프레임 없이 끝난 MJPEG에서 웹 프로세스가 죽으므로 유휴 스트림도 1초마다 유지하고 종료 경계로만 끝낸다.
- 왼쪽 클릭으로 조준 지점에 1kg 공을 5~25m/s(기본 12m/s)로 발사하고 발사·적중 횟수를 표시한다. 공은 최대 8개이며 5초 후·초기화·지형 변경 시 제거된다.
- 평지·큰 돌·6cm 계단·돌과 계단 혼합 지형을 선택한다. 장애물에는 실제 MuJoCo 물리 충돌이 적용된다. Walking·Careful Walk·Safe Crouch·Standing·Damping·Zero Torque 버튼으로 전환한다. 넘어진 뒤에는 ‘로봇 초기화’를 누른다.
- Careful Walk의 평가 완료 모델은 `.agent/operation_center/simulation_policies.json`으로 고정한다. 학습 ID·ONNX/제어 설정 해시·입출력을 검증하고 액션 아래에 모델 이름을 표시한다.
- ‘사람 모션 교사(실험)’은 평지에서 233입력 교사 ONNX를 학습과 같은 r1lab 모션 매칭(재고정은 평가 기준 0.3m/0.3rad)·관측 함수로 실행한다. W/S·우클릭 방향만 따르고 A/D 옆걸음은 자료가 없어 무시한다. 교사와 매칭 라이브러리는 `.agent/operation_center/reference_teacher.json`의 경로·SHA256으로 고정·검증한다. 첫 선택 때 수 초 불러오며 참조 클립·전환·재고정·오차를 표시한다.
- ‘통합 정책 S1(실험)’은 평지에서 전신 학습 계열(r1wb)의 1198입력 ONNX 하나를 실행한다. `.agent/operation_center/unified_policy.json`의 경로·SHA256으로 고정하고, `lateral` 표시가 없는 모델은 A/D 단독 입력을 무시한다. 선택 파일들의 변경은 Simulation 작업 프로세스 재시작 때 적용하며, R1 배포 정책과는 별개다.
- ‘DynamicMode’는 전신 학습 계열(r1wb)의 현재 스택(지시 → 목표 → 조향 고리 → 운동 토큰 머리 → 추종 정책)을 평가와 같은 실행기로 돌린다. 별도 프로세스가 `.agent/trainer/rlinf/.venv`와 PC GPU를 쓰고(절전 모드에서 실시간의 약 0.8배) 다른 액션 선택·30초 무입력 시 끝난다. 구성은 `.agent/operation_center/dynamic_mode.json`의 경로·SHA256으로 고정하며 R1 배포 정책과는 별개다.
- DynamicMode 입력: W/A/S/D 8방향·걷기 속도, 우클릭 방향(먼저 돌고 나서 걷는다), 자세 버튼(앉기·일어서기), 문장 지시 텍스트 박스(2B 목표 모델이 머리 카메라와 함께 읽어 27개 지시 중 하나로 바꾼다. 처음 한 번 수십 초 불러온다). 마지막 입력이 우선이다.
- 조작은 이 PC의 물리 시뮬레이션에만 적용한다. 탭을 벗어나면 일시정지하고 창 포커스를 잃으면 키 입력을 해제한다. ‘자동 생성 학습 영상’은 Trainer 탭으로 이동한다.

## Trainer
- `http://127.0.0.1:8797/#trainer`는 전체 학습 이력·상태·산출물 관리 화면이다. 영상 생성 대상이 아닌 과거 학습도 표시한다.
- ID·설정 검색과 액션·상태 필터, 진행률·반복·평가 추이를 제공한다. 실행 여부는 GPU 서버 프로세스를 10초마다 확인하며 연결 실패는 미확인으로 표시한다.
- 새 학습은 필수 등록된 목적·설정·초기화·완료·중단·오류 기록을 표시한다. 실행 중단 시 원인도 확인할 수 있다.
- 학습별 정책·체크포인트·로그·평가·영상·전체 모션·환경 모델·재현 메타데이터의 목록과 크기를 확인하고 다운로드한다.
- 데스크톱 앱이 켜져 있을 때 10분마다 새 체크포인트를 이 PC에서 평가·렌더링한다. 창을 닫으면 평가·렌더링·Simulation·상태 수신 자식도 종료한다.
- `--headless`는 조회 서버만 켠다. 브라우저 서버에 자동 영상도 필요하면 `--with-results`를 추가하며, 서버 종료 시 함께 정리한다. GPU 서버 학습과 `trainer-sync`는 유지한다.
- 목록은 5초마다 갱신한다. ‘새 영상 자동 표시’를 끄면 현재 선택한 영상을 유지한다.
- 영상은 저장된 산출물 미리보기이며 최신·최고·반복별로 선택한다. 관절 궤적은 다운로드로 제공하고 실시간 조작은 Simulation에서 한다.
- S7은 실제 공 연사 24사례의 넘어짐과 원시 평가 JSON도 보존한다. v4 점수는 공 충돌 실패를 추가 반영하며, 공 충돌 데모 영상과 24사례 평가를 구분해 표시한다.
- S7의 `gait_it<반복>.json`은 제조사와 같은 실현 속도의 착지·하중·흔들림 비교와 원시 보행 측정을 담는다. 실패·속도 미달·착지 결측은 비교 미산출이다.
